SECTION 1 — PROBLEM STATEMENT & UNDERSTANDING
1.1 The Core Problem
Companies today manage employee goals using spreadsheets, emails, and offline reviews.
This creates:
• Managers cannot see team progress in real time
• Employees do not know how their work connects to company priorities
• HR has to manually piece together data during appraisals
• No accountability — things fall through the cracks
The Solution: Replace all of that with a clean, digital, role-based web portal covering the full
goal lifecycle — creation, approval, quarterly tracking, and reporting.
1.2 The Three User Roles
Role Who They Are Core Responsibility
Employee Any staff member Creates goals, submits for approval, logs quarterly
achievement
Manager (L1) Direct line manager Reviews and approves/edits/returns goals, reviews
check-ins
Admin / HR HR team or system Controls windows, manages org hierarchy, exports
admin reports
1.3 Key Concepts Explained
What is a Goal?
A goal is something an employee wants to achieve by end of year. It has a clear target, a
timeframe, and a measurable metric.
Example: "Achieve Rs.40 Lakhs in regional sales revenue by 31st March 2026"
What is a KPI?
KPI (Key Performance Indicator) is the measuring stick for a goal. It answers: How do we know
if you succeeded?

1.5 What are Shared / Departmental Goals?
When a manager wants the whole team to share one goal, they "push" it to multiple employees
at once.
• Goal title and target are FIXED — employees cannot change them
• Each employee can adjust only the WEIGHTAGE of the shared goal
• When the primary owner updates their achievement, it automatically SYNCS to all linked
employees
Example: "Every sales rep must achieve Rs.40L revenue" — pushed to all 8 sales reps by the
manager.

4.4 Progress Score Formulas (DB Trigger + Live Preview)
-- DB Trigger fires on check_in INSERT or UPDATE
IF uom_type = numeric_min THEN
score = LEAST((actual_value / target_value) * 100, 100)
ELSIF uom_type = numeric_max THEN
score = LEAST((target_value / actual_value) * 100, 100)
ELSIF uom_type = timeline THEN
IF actual_date <= target_date THEN score = 100
ELSE score = 0
ELSIF uom_type = zero_based THEN
IF actual_value = 0 THEN score = 100
ELSE score = 0
-- Always round to 2 decimal places
-- Always handle division by zero gracefully

SECTION 9 — AI PROMPTING STRATEGY
9.1 Seven Golden Rules of Vibe Coding
14. Always give CONTEXT before asking to build — paste master context first
15. One feature at a time — never ask for everything at once
16. Always specify the tech stack in every prompt
17. Always reference the design system (black + yellow) explicitly
18. Always tell the AI what NOT to do — prevents unwanted choices
19. When it makes a mistake — correct precisely, not vaguely
20. Always ask it to explain what it built after — catches misunderstandings
9.2 The Master Context Prompt
Save this and paste it at the START of every new AI conversation or when starting a new
feature:
I am building a Goal Setting & Tracking Portal for a hackathon.
TECH STACK:
- Framework: Next.js 14 (App Router only — never Pages Router)
- Styling: Tailwind CSS + shadcn/ui (never raw CSS)
- Database: Supabase (PostgreSQL + Auth + Realtime)
